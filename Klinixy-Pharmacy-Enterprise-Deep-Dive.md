## §5 — Klinixy ecosystem blend (PROPOSED contracts — VERIFY FIRST, §0 rule 8)

The ecosystem is 4 apps on Firebase project **klinixy-68521**: **main (customer) app · pharmacy app (this repo) · rider app · admin panel**. This repo is the pharmacy leg. The contracts below are PROPOSED from the pharmacy side's needs — Gemini must read the main-app / rider-app / admin repos (or ask Maalik for their paths) and reconcile every field name before writing order code. - **Why location matters:** the main app assigns an order to the NEAREST pharmacy by GeoPoint distance. Without pharmacy coordinates (§6), nearest-pharmacy assignment cannot work — that is the concrete reason P2 comes before P8.
- **Proposed `orders` (top-level collection):** id · pharmacyId · customerId · customerName · customerPhone · deliveryAddress (text) · deliveryLocation (GeoPoint) · items[{medicineId, medicineName, qty, unitPrice, totalPrice}] · subtotal · deliveryFee · total · paymentMethod (COD/UPI/online) · paymentStatus · status (`placed → accepted → packed → rider_assigned → picked → delivered`, or `rejected`/`cancelled`) · prescriptionUrl (nullable) · createdAt · updatedAt · statusHistory[{status, at, by}].
- **Pharmacy app's job (P8):** live-listen `orders where pharmacyId == myId AND status == 'placed'` → new-order alert (sound/badge) → Accept / Reject (with reason) → mark Packed → hand over to rider (status `rider_assigned`/`picked` is set by rider/admin, pharmacy only reads it) → Delivered is set by rider. - **Shared rules of the road:** one canonical order doc (no per-app copies); status moves forward only (no going back except `rejected`/`cancelled` with reason); every status change appends `statusHistory`; money fields are numbers (paise-safe: store ₹ as double with 2-decimal rounding at write time, never float-math in the UI); timestamps are server `Timestamp` (never device clock).
